# Whimsy Web handoff (extension, Dashboard mode, community website)

## Run
- Extension: `npm install && npm run build`, load `dist/` at chrome://extensions (Developer mode). `npm test` runs 14 suites; `npm run live-check` fetches the real demo dashboard sources.
- Website: `cd web && npm install && npm run db:migrate && npm run db:seed && npm run dev`.
- Env (web): `SITE_URL`, `EXTENSION_IDS` (id from chrome://extensions), `MODERATOR_EMAILS`, `DATA_DIR`, `AUTH_SECRET` (required in production), `RESEND_API_KEY` + `EMAIL_FROM` (email), `AUTH_GOOGLE_ID/SECRET` (optional), `EXTENSION_STORE_URL` (optional).
- Extension build: `WHIMSYWEB_SITE_URL` (https in production) and `WHIMSYWEB_SITE_ORIGINS` set the only origins allowed in `externally_connectable`.

## Tested
- Unit suites (all pass). Real-browser e2e: `scripts/e2e/website-extension.cjs` (browse, apply with confirmation, live restyle of Wikipedia, undo, sign-in, publish + validation, report, moderation, extension-to-website draft transfer).
- Not tested live: the side panel Share button (needs the real side panel) and the AI assistant (needs an API key).

## Dashboard mode
Removed from `main` to keep the extension's permissions small for store review. The complete, tested feature is on the `dashboard` branch (tag `dashboard-v2-working`). To bring it back, merge that branch or revert the "Remove Dashboard mode" commit.

## Design previews
- When a design is made, applied, or "Create/Refresh preview" is chosen, the extension makes a tiny blurred preview. The content script first replaces text with neutral bars and blurs images in place (no AI), the visible tab is captured and the page restored immediately, then the screenshot is shrunk to a few dozen pixels (this removes detail for good), enlarged smoothly, softly blurred and lightly sharpened. Only that ~5 KB image is stored. The full screenshot is never saved or sent. Nothing is captured in private windows. Settings has a switch and "Clear all previews".
- Tests: `tests/preview.test.ts` (rules and pixel steps) and the real-browser `scripts/e2e/previews.cjs` (needs `WW_OUTDIR=dist-e2e WHIMSYWEB_E2E=1 node build.mjs`, which adds a test-only hook that is never in `dist/`). Previews are not guaranteed anonymous: text drawn into a canvas or a closed shadow root is only covered by the shrink.

## Generated illustrations (OpenAI models only)
- A "Generate illustrations" checkbox appears next to Attach image when an OpenAI model is selected. ON: the model gets the art-director instructions and an `illustrations` field; the extension asks `gpt-image-2.5-flare` (images API) for each picture (max 4, descriptions only, nothing from the page), shrinks them to small WebP and stores each as `art:<id>`. Designs refer to them as `ww-asset-art:<id>` tokens, which the CSS sanitizer allows and the content script swaps for the real image after sanitizing. OFF: CSS-only designer instructions (which may suggest turning illustrations on). Claude models ignore the checkbox.
- Pictures are written in the same storage write as their design, and unreferenced ones are deleted after deletes. Shared community themes lose their pictures (they become blank). gpt-image-2.5-flare may need OpenAI organisation verification; if it fails the design still saves and the reply says why. Image calls are counted in Token usage under gpt-image-2.5-flare (OpenAI-reported tokens, or the documented size if none are reported).

## Whimsy Lab (prompt test bench, model-driven)
- A separate extension in `lab/` (`npm run build:lab`, load `dist-lab` unpacked). The model is given TOOLS and the user’s system prompt decides the whole workflow: `take_screenshot` (the live page as rendered, optional scroll), `apply_css` (live preview; the safety filter reports how much it kept), `generate_image` (`gpt-image-2.5-flare`; shapes, transparency, quality, `reference_ids` for style reference = earlier pictures or the current page; no count limit; needs an OpenAI key, works with any design model), `submit_design` (final; css optional = what was last applied). `lab/src/agent.ts` is only the loop (Anthropic messages tool use / OpenAI Responses, stateless with encrypted reasoning items): call the model, run the tools it asks for, return results (images included), repeat until it submits. The only guard is a stop after 200 model turns and the Stop button. The system prompt is sent exactly as typed (blank = none); how to use the tools is in the tool definitions. Whimsy Web’s own theme on the page is switched off during runs. Each result keeps every step (what the model said, each tool call, screenshots, pictures) so you can see whether planning, image generation or CSS caused a poor result. Starter prompts: Agent workflow (example), Art Director, Experimental Mode (verbatim), current Whimsy Web prompt. Its keys, prompts and results live only in its own storage.
- The main extension is unchanged (fixed one-call workflow; optional Generate illustrations).

## Page outline extras (src/content/extract.ts)
- Layout summary (`layoutSummary`): window size, page height, landmarks, biggest first-screen blocks, repeated items (cards) with sizes, positions and how many photos/videos each holds. Noise filtered: wrappers of the same box, SVG internals, invisible overlays, text elements.
- Original colours and fonts (`styleSummary`, only when no design is applied): header, nav, main, sidebar, footer, a repeated item, h1, h2, a link, a button, a text input: background (or what shows behind a see-through one), text colour, font, border, radius.

## Design sessions and linear Back/Forward (branch feature/design-sessions)
- A chat is a design session: Intensity and Polish are shown only before its first design (or with Start fresh) and stored as conversation.session; later turns are refinements (no level section, Polish Quick; pictures stay available if the session used them) and the model scopes each request itself.
- Revisions = assistant replies with a snapshot that are not discarded (src/shared/revisions.ts). conversation.revisionIndex = the applied one (absent = latest). Mutate navigateRevision (and the old restore, now "Go to this version") writes design + chat in ONE commit and records an event (back/forward) shown as an activity line.
- A new AI turn while on an older revision marks the later revisions discarded (kept in the transcript) and clears revisionIndex: no branches.
- The model gets a <design_history> block (which version is applied, what is undone, recent moves) and each earlier reply is labelled [version N ...] / [discarded ...]; the user's words are untouched. <current_design> is always the applied version.
- Tests: background.test.ts (sessions + navigation block); e2e %TEMP%/blur/sessions-e2e.cjs (17 checks, real panel UI).

## Polish (separate from Intensity): src/background/polish.ts
- Bar under Intensity (ww.polish): 1 Quick (one pass), 2 Polished (one screenshot, one targeted-fix pass), 3 Studio (screenshot, critical rework with new or edited pictures when Intensity >= 2 and an OpenAI key, screenshot, final refinement, screenshot, then `pickBestVersion` compares the three screenshots and the strongest version is saved). Sent as msg.polish.
- Runs after the first save in generateTurn. Every version is saved as the chat design + the turn snapshot (follow-ups build on it); a change made meanwhile is never overwritten; Stop keeps the last saved version; private windows are skipped with a note; if the tab is not on screen (another tab, minimised window) the review waits up to 5 minutes for the user to come back (panel shows "Waiting for you to return..."), then ends cleanly. A note under the Polish bar at levels 2-3 says to stay on the tab. Waits for the page to report the new version (ContentState.versions) before each screenshot. Progress goes to the panel as ww:progress.
- Pictures can be edited: plan_artwork pictures take edit_of (an existing ww-asset-art token) -> OpenAI /images/edits with that picture as input. Names of pictures painted during a review carry over to later passes.
- Tests: tests/polish.test.ts (mocked chrome + APIs). E2E: e2e build exposes __ww.generate; %TEMP%/blur/polish-e2e.cjs drives all three levels in real Chrome with the APIs mocked by Playwright routes.

## Intensity (replaces the Generate illustrations checkbox)
- Bar with 5 dots under the toolbar (`IntensityBar` in App.tsx, saved in localStorage ww.intensity; the old ww.illustrations=1 becomes 2). Levels in `INTENSITY_LEVELS` (shared/types.ts): 1 Simple (CSS only), 2 Illustrated (the artwork steps as they were), 3 Enchanted, 4 Immersive, 5 Chaos. Sent as msg.intensity; 2+ needs the OpenAI key.
- Each level is its own prompt (anthropic.ts): ROLE + design section + SHARED (follow-ups, layers, tokens, images, usability rules) + artwork steps. Levels 1-2 use DESIGN_STEPS and CLAUDE_ART unchanged; 3-5 use LEVEL_DESIGN[level] instead of DESIGN_STEPS, and `artStepsFor(level)` swaps in LEVEL_ART_USE (Chaos: pictures throughout, buttons and banners included; no picture counts anywhere, only a code safety stop of 24). No calm advice is left in the higher levels to contradict them.

## Claude + generated illustrations (two steps)
- Checkbox Generate illustrations (any model). With a Claude model it needs Settings > OpenAI API key for illustrations (settings.openaiKey).
- `generateDesignWithArt` (src/background/anthropic.ts): step 1 Claude calls `plan_artwork` (plan, art_direction, pictures with id/use/prompt/shape/transparent/quality/size) or goes straight to submit_design; pictures are painted by gpt-image (`generateIllustrations`, art direction in front of every prompt, first picture used as the style reference for the rest, quality and stored size from Claude); step 2 Claude sees the pictures as made plus its own plan, revises, and calls submit_design using url("ww-asset-<id>"). Both steps send the same tools + system so the cached prefix is reused. No count limit in the prompt (safety stop MAX_CLAUDE_PICTURES = 24). Prompt text: CLAUDE_ART.

## Theme matching (no AI) - runs BEFORE the readability fix
- `src/shared/theme.ts` (pure: which colours are off-theme, what they become; only NEUTRAL whites/greys/blacks are ever remapped) and `src/content/theme.ts` (DOM). Order after a design applies: 1) site styles: the site’s own stylesheets are read (other-origin sheets fetched by the background worker via `ww:fetchSheet`, private addresses blocked) and every rule painting a whitish/greyish surface, border or colour variable, including :hover/:focus/:focus-within/open states, gets an override in the theme colours as `:where(original selector){...!important}` placed before the design’s styles (the design wins ties); rebuilt only when the designs or the set of stylesheets change (max every 10s). 2) live safety net: focus/click/hover/key/transition/new-element events re-check only the element, ~6 parents and an opened search/menu box, at most every ~120ms; corrections are re-measured so they end when the state ends. 3) doubled borders: a child drawn almost exactly inside a parent with the same border loses its border. Then readability. Page churn (feeds) re-runs these at most every 5s. Setting: Settings > Readability and colours > Keep site colours on the theme (prefs.themeFix, default on). Not covered yet: box-shadow colours, gradients/images, script-injected inline styles until an interaction happens.

## Readability (programmatic contrast fix, no AI)
- `src/shared/contrast.ts` (pure WCAG maths + `fixColor`) and `src/content/contrast.ts` (DOM). After a Whimsy Web design is applied, every visible piece of text is compared with the colour really behind it (parents composited over white; text over an image or gradient is only counted as unknown). Below 4.5:1 (3:1 for large text) the text colour is nudged the way it already leans: darker text darker, lighter text lighter, hue kept, smallest change that passes; if that direction can never pass (dark text on mid grey) it flips. Fixes are one stylesheet (#ww-contrast-style) plus data-ww-fix markers, never page rewrites; clearing restores the page. Re-runs (throttled) on page changes; off when the design is off or Show original. Setting: Settings > Readability (stored in the secret-free `prefs` key, default on). The This site tab shows how many colours were adjusted. The Lab has a `check_contrast` tool (report, optional live fix). Not covered: overlapping borders/clipped edges, hover states, text in canvases/videos, pseudo-element text.

## Limits
- Image URLs in sandboxed pages are allowed over https (`img-src https:`), so a script could encode that dashboard's own data in an image URL. Scripts have no access to API keys or other extension data.
- Legal pages are drafts needing owner review. Seed themes cover Wikipedia and Hacker News only (the sites verifiable here). Dashboard collection runs only while the browser is open. Nothing is pushed to GitHub yet.
